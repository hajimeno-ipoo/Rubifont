# Rubifont Sans 0.6.23

漢字の上にひらがな、登録した英単語の上にカタカナを表示するフォントです。同じ文章の中で、日本語と英語の両方に読みを添えられます。

[公開済みの配布版](https://github.com/hajimeno-ipoo/Rubifont/releases) · [ソースコード](https://github.com/hajimeno-ipoo/Rubifont)

## 主な機能

- 漢字・単語に、辞書に基づくひらがなの読みを表示します。
- 英語2,684語・8,113表記に対応します。`save`・`Save`・`SAVE`のような小文字・頭だけ大文字・全大文字に同じ読みが付きます。
- 本文の文字データは元のままです。読みはフォントの文字の形として表示します。
- Webでは`font-feature-settings: 'ss01' 1`で日英の読みをまとめて非表示にできます。

横書きのRubifont Sans Regularと、太さを250〜900の範囲で指定できる可変フォントRubifont Sans VFを同梱しています。読みの対応範囲は共通です。別のフォント名なので、両方をインストールして使えます。

| 書体 | インストール用 | Web用 |
| --- | --- | --- |
| Rubifont Sans Regular | `RubifontSans-Regular.otf` | `RubifontSans-Regular.woff2` |
| Rubifont Sans VF | `RubifontSansVF.ttf` | `RubifontSansVF.woff2` |

## 使い方

### Macで使う

1. 配布ZIPを展開します。
2. `RubifontSans-Regular.otf`を開き、Font Bookでインストールします。
3. 使いたいアプリで、フォントを「Rubifont Sans」に指定します。

可変フォントを使う場合は`RubifontSansVF.ttf`をインストールし、「Rubifont Sans VF」を選びます。太さをどのように指定できるかは、利用するアプリによって異なります。

読みが切れる場合は行間を広げてください。表示はアプリのOpenType対応や組版の設定によって異なります。

### Webサイトで使う

`RubifontSans-Regular.woff2`をページと同じフォルダに置き、CSSで読み込みます。

```css
@font-face {
  font-family: 'Rubifont Sans';
  src: url('./RubifontSans-Regular.woff2') format('woff2');
  font-weight: 400;
}
.reading {
  font-family: 'Rubifont Sans', sans-serif;
  font-weight: 400;
  line-height: 1.9;
}
```

```html
<p class="reading">日本語で Hello。Settings を開いて Save。</p>
```

可変フォントは`RubifontSansVF.woff2`を置き、次のように読み込みます。`font-weight`で250〜900の太さを指定できます。

```css
@font-face {
  font-family: 'Rubifont Sans VF';
  src: url('./RubifontSansVF.woff2') format('woff2');
  font-weight: 250 900;
}
.reading-variable {
  font-family: 'Rubifont Sans VF', sans-serif;
  font-weight: 400;
  line-height: 1.9;
}
```

```html
<p class="reading-variable">日本語で Hello。Settings を開いて Save。</p>
```

### 同梱ページで試す

ZIPを展開したフォルダで、次のHTMLファイルを開いてください。

| ファイル | 内容 |
| --- | --- |
| `index.html` | 自分の文章で試せる見本 |
| `usage.html` | 使い方とライセンス原文 |
| `english.html` | 英単語とカタカナ読みの対応一覧 |

登録した短縮形・所有形は、`can't`・`can’t`のような直線形と曲線形のアポストロフィに対応します。未登録の短縮形や所有形へ、自動で読みを付ける機能はありません。登録済みの単語の末尾に単独の`'`・`’`が付く場合も、記号を残したまま読みを表示します。たとえば`singin`・`singin'`・`singin’`には「シンギン」が付きます。`singin'x`や未登録の`save's`のように、アポストロフィの後ろにも文字が続く表記は対象外です。

## 対応範囲と制限

日本語は本家の辞書に、Rubifont独自の追加辞書を合わせています。追加辞書では24漢字の通常読みを指定しています。「字」は通常「じ」、住所などで用いる「あざ」は別読みとして収録しています。同じ漢字が単独で現れるほかの語にも適用されます。たとえば「重＝かさ」「出＝だ」「失＝な」の指定は、「重い」「出る」「失う」にも適用されるため、異なる読みでは別読みの指定が必要です。「来」は「き」、「止」は「と」を通常表示し、「く」「や」も別読みとして収録しています。「来る」を「くる」、「止めた」を「やめた」と表示する場合は別読みの指定が必要です。フォント単体では、送り仮名や文脈による自動切替には対応していません。

0.6.18では「1日・１日＝いちにち」に対応しました。数字1の既存の「ひと」を1番に保ち、「いち」を2番へ追加し、日には「にち」を指定します。「楽ありゃ」「苦あり」「声で」「楽に」は既存の読みを送り仮名表へ結び付けました。「人生楽ありゃ」は文脈が一致する場合だけ3漢字へ読みを指定し、通常の「人生楽」の表示は変えません。「中走＝なか・はし」を追加して「ゴミの中走ってく」の読みを補いました。英語はcandy＝キャンディ、pretty＝プリティ、doll＝ドールの3語を追加しています。

0.6.17では「声聞＝しょうもん」の通常読み固定を外しました。「声聞」は通常「こえ・き」を表示し、仏教用語の「しょうもん」は別読みの2番として残しています。「声聞き」の文脈指定も取り除き、「あなたの声聞きたくて」はフォントの通常表示で「こえ・ききたくて」と読みを付けます。

0.6.16では「2つ・２つ＝ふたつ」「不満の声＝ふまんのこえ」「声聞き＝こえき」「金のハンドル＝きんのハンドル」の文脈指定を追加しました。通常の「声聞＝しょうもん」「金＝かね」は維持します。「鼓動焼」と「時感」にはそれぞれ「こ・どう・や」「とき・かん」を追加し、「胸の鼓動焼きつけろ」「あの時感じた」の連続する漢字でも読みを表示します。英語の感嘆詞「ah」には指定どおり「アー」を追加し、AHにも同じ読みを表示します。

0.6.15では「暗闇走」に「くら・やみ・はし」を登録し、送り仮名表へ「人[ひと]が」を追加しました。半角・全角の数字1・2には、利用側が`salt`の1番で選べる「ひと」「ふた」の字形を追加しています。`context-readings.json`には「1つ・１つ」「2人・２人」「あの娘」の読み指定を収録し、同じ版のフォントと組み合わせて利用できます。「2人」は2の「ふた」と人の「り」を合わせて表示します。数字の直前が別の数字なら適用しません。「あの娘」は「こ」を選び、通常の「娘＝むすめ」は維持します。文脈の照合と読みの指定は利用側の処理が必要で、MusicPrayerもその処理と同梱データを更新します。

0.6.14では送り仮名表へ「出[で]を」を追加しました。更新した対応表を使うアプリでは「想い出を」「思い出を」の「出」を「で」に切り替えます。通常の「出＝だ」は維持し、「出して」「出す」の読みを保ちます。利用側に保存済みの読みがある場合は、更新表の反映と読みの再生成が必要です。

0.6.13では、全角数字の「１つ」に「ひとつ」、「２人」に「ふたり」を表示する規則を追加しました。本文の数字表記を保ち、「１１つ」「１２人」など長い数字の末尾だけに読みを付けることを防ぎます。読みを非表示にする`ss01`にも対応します。

表示側が文字種ごとに分割する制限は残ります。「２人」単独や「２人で」、「もう１つだけ」では表示できますが、「わたしたち２人で」は数字が前のひらがな側へ分かれるため読みが出ません。半角・全角を混ぜた数字など、文字種の境界を越える場合は、数字の直前を確認する規則も届かないことがあります。

0.6.12では添付リストから英語21語と、日本語の別読み「方＝ほお」「娘＝こ」「哀＝かなし」を追加しました。「方が＝ほおが」「哀く＝かなしく」は送り仮名の対応表にも追加しています。「娘」の通常読みは「むすめ」のままで、「こ」は別読みとして選択できます。

送り仮名に応じた読みの切り替えに使う対応表を、`okurigana.json`として同梱しています。本家の送り仮名データと修正指定を土台に、Rubifontの読み候補・通常読みに合わせて再生成します。「来ない→こ」のような対応を参照できます。同じ漢字列と送り仮名の組み合わせは本家を優先し、本家が曖昧としている対応も自動では読みを選びません。本家にない独自の対応だけを、`rubifont/okurigana.json`で管理します。利用側の読み切替処理で、同梱の対応表と、使用する書体の`.ivs.json`を組み合わせてください。既存の`createOkuriganaReader`に対応する形式です。0.6.7では、本家の原本・修正指定36,993組と独自14組を統合し、必要な16,339組（うち曖昧977組）を出力しています。

日本語は228,369の読みパターンと、単独漢字1,725字への読み設定を収録しています。パターン数は生成規則の数で、正しく読める単語の総数ではありません。部品の組み合わせで同じ読みになる単語もあります。日本郵便の住所データは、字形数の上限を超えるため収録対象から外しています。

0.6.11では「夜[よる]待[ま]」を追加し、「凍える夜待ち合わせ」のように空白なしで続いても「夜＝よる」「待＝ま」を表示します。ほかの文章にある「夜待」にも同じ指定が適用されます。本家の単独漢字の読みを適用する規則は変更していません。

英語は同梱の`english-readings.json`にある2,684語が対象です。複数形や活用形も一覧にある表記だけに対応します。カタカナは発音の目安で、未知語、任意の大小文字混在、文脈による発音の変更には対応しません。

日本語も、辞書や文脈による限界があり、誤読や読みが付かない場合があります。送り仮名による読み分けを補助するJavaScriptは同梱していません。

単語が別の要素や書式に分かれると、フォントから見える範囲も分かれます。英語では、前後の英字・数字・アクセント文字・アンダースコア・アポストロフィーを確認し、単語の一部分への読み付けを抑制します。

WebKitでは、異体字セレクターによる単語の別読み指定が正しく働かない場合があります。異体字セレクターや`salt`で読みを指定する場合は、同じ配布版の、Regularには`RubifontSans-Regular.ivs.json`、可変フォントには`RubifontSansVF.ivs.json`を使ってください。指定番号は更新によって変わる場合があります。

0.6.9では、読み候補が1つの漢字にも明示指定の規則を生成するよう修正しました。通常読みがない「綾」なども、`salt`の1番またはVS242で候補の読みを選べます。0.6.6〜0.6.8で説明していた、指定しても読みが表示されない問題への修正です。通常の表示、`ss01`による読みの非表示、複数候補からの選択方法は従来どおりです。報告対象414字と、その条件を含む910字すべてで、RegularとVF・Mediumの読み表示をCore TextとSwiftUIで確認しました。確認結果の詳細は`verification.md`をご覧ください。

Firefoxの描画は未確認です。確認した環境と検証結果の詳細は、同梱の`verification.md`をご覧ください。生成元・容量・SHA-256は`build-manifest.json`に記録しています。

## 開発者向け：フォントの再生成

再生成には、配布ZIPとは別に[ソースコード](https://github.com/hajimeno-ipoo/Rubifont)を取得してください。リポジトリ内でNode.js 22.18以上と、`package.json`で指定したpnpmを使います。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm rubifont
```

出力先はリポジトリ直下の`outputs/`です。初回はAdobeの元フォントを取得し、`.cache/fonts/`へ保存します。日本語の追加辞書は`rubifont/japanese.json`、英語の一覧は`rubifont/english.json`で編集できます。

`rubifont/japanese.json`の`add`には本家にない漢字列と読みだけを保存し、`pin`には希望する通常読みを保存します。日本語の読みは、次のコマンドで追加できます。

```sh
pnpm rubifont:japanese '来[く]る'
```

この例の「来＝く」は本家にあるため、`add`へは保存しません。登録時とフォント生成時の両方で、本家と同じ漢字列・読みを持つ項目を重複として除きます。漢字ごとに読みを付けるか、複数漢字をまとめて付けるかが違っていても、同じ読みなら本家のルビの区切り方を使います。0.6.8で既存の`add`27件を重複として除き、0.6.11で「夜[よる]待[ま]」を1件追加しました。0.6.12では不足していた「方[ほお]」「娘[こ]」「哀[かなし]」を加え、`add`は4件です。0.6.15で「暗[くら]闇[やみ]走[はし]」を加え、0.6.16で「鼓[こ]動[どう]焼[や]」「時[とき]感[かん]」を加え、「声[こえ]聞[き]」も加え、0.6.18で「中[なか]走[はし]」を加え、0.6.22で「灯[ともし]」を補い、現在は10件です。`pin`は24漢字の通常読み指定です。0.6.17で「声聞＝しょうもん」の固定指定を外しました。

フォントが扱うのは漢字列です。「来る」の送り仮名から「く」を選ぶ対応は別に管理します。送り仮名に応じて読みを選ぶ独自の対応は、次のコマンドで登録します。

```sh
pnpm rubifont:okurigana '来[こ]ない'
```

本家に同じ漢字列と送り仮名の組み合わせがあれば、本家の対応を使い、独自ファイルには追加しません。本家にない対応だけを`rubifont/okurigana.json`へ保存します。追加後は`pnpm rubifont`で配布用の対応表を再生成します。独自対応で必要な読みは生成時にフォントの候補へ追加しますが、通常読みの優先指定は変更しません。


0.6.19では「人ゴミ」の「人＝ひと」を選ぶ条件をcontext-readings.jsonへ追加しました。既存の読み候補を使い、単独の「人」の通常表示は変えません。利用側の読み選択処理が必要です。


0.6.20では「全部抱きしめて」の抱だ、「入れて」の入いをcontext条件で選び、「終わんないで」の終おを送り仮名表で補います。既存の候補・通常読みは保ちます。


0.6.21では「砂遥か＝すなはるか」「糸激しく＝いとはげしく」「記憶遥か＝きおくはるか」「やわらかな額＝やわらかなひたい」「心奪われ＝こころうばわれ」の文脈条件を追加しました。英語prototype＝プロトタイプも追加しています。既存の通常読みと、これまでの条件は保持します。


0.6.22では「来ぬ＝こぬ」を送り仮名表へ追加し、「消さないで灯火」でともしびを選べるようにしました。灯火の通常とうかを保ち、選択用に不足していた灯ともしの字形を補っています。英語shelter＝シェルターを追加し、登録済みcandy・pretty・dollはそのまま使います。


0.6.23では「負けぬ様に＝まけぬように」「抱き上げる＝だきあげる」「傍に＝そばに」「明日の＝あすの」を補いました。負まは既存の通常読みを使い、様よう・抱だは対応する表記のcontextで選びます。傍に・明日のは不足する送り仮名キーを補い、単独の明日あしたや抱いたいだは保持します。
